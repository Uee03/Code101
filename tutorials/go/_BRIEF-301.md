# Go track brief - 301 Super Hero to Legendary

## Learners and outcome
Developers who finished Go 201 (`201-hero-to-super-hero/`) and have shipped some Go services. Voice: assume 201; trade-offs, failure modes, "when not to use this", measurements to take (never invented numbers: every performance number is one the learner measures), production checklists, ADR-style decisions, security and operations. Outcome: the learner can design and review concurrent code, find and fix data races, profile and benchmark, structure a service by dependency direction, build and test gRPC services, make calls resilient, observe a service with logs, metrics and traces, secure it and its supply chain, and release it reproducibly with a production checklist. The full production API is the capstone `capstones/backend-go`; lessons link to its chapters (idempotency 04, identity 05, Docker 06, hardening 07) instead of duplicating them.

## Scope choices
- Standard library first; external modules only where the real world uses them (errgroup, rate, gRPC, Prometheus, OpenTelemetry, JWT). No web framework, no mocking library, no DI container.
- The three exercises of each phase are small and focused; lessons 05 (overlay on the lesson code) and 09 (a review, not a coding task) differ on purpose.
- Security, identity and API craft are taught inside code, not as separate lessons, consistent with the course rule; the identity provider and a database-backed idempotency store stay in the capstone.
- Each lesson has: ADR, "when not to use", failure-mode table, measurements to take, production checklist. Lesson 09 gathers the checklist for the whole level (28 items with IDs) and the review exercise uses those IDs.
- Time estimates (first-timer): 70, 60, 75, 80, 90, 90, 100, 110, 120 minutes; every lesson marks a break point; two sittings are normal at this level.
- The race detector needs a C compiler on Windows and Linux; lesson 02 says so before the first `-race` command and gives WSL2 as the simple Windows route.
