# web 101 (lessons 01 to 12, HTML, CSS, JavaScript, TypeScript) walk-through by Sam

**Persona:** Sam, marketing, never coded. Used only what each lesson had already taught; a term used before it is defined is a finding.
**Method:** unzipped `dist/packs/web-101-all.zip` into a clean temp folder, then typed every file of every lesson literally from the lesson text (including intermediate versions: `npm init --yes` output, the broken `sessions: "three"` file). Copied each exercise starter into its own `-try` folder, made the requested change **before** opening the solution, then compared with the solution. Served the folder with `python -m http.server` (port 18901, stopped afterwards) and fetched every page and every referenced file. Ran `node`, `npm install`, `npx tsc` exactly as written (Node 26.13.1, npm 11.20.0, TypeScript 7.0.2, Windows PowerShell 5.1). Triggered the Common-mistakes errors that a script can trigger. Nothing was installed or uninstalled; the work folder was deleted afterwards.
**Not simulated (no browser):** how any page looks, clicks, keyboard use, `file:///` behaviour, Live Server, DevTools. See "Needs a human with a browser".

Every id the JS/CSS uses exists (`#greet`, `#status`, `#name`, `#bio`, `#skills`, `#todo-form`, `#task`, `#tasks`). - `search.svg` in the pack is byte-identical to `assets/art/icons/ui/search.svg`; CC0 text is present. All external links in the lessons return 200 (checked with HEAD).
- Arithmetic and facts checked: card 320 - 48 - 8 = 264, content-box 376, exercise 252; flex wrap points (about 620px for three cards); `min-width: 700px` includes 700; cascade results in lesson 04.
- Node output of 08 (final and solution), 09, 10, 11, 12 matches the "Expected output". `package-lock.json` produced by the lesson's `npm install` command is byte-identical to the pack's for lessons 10, 11, 12.

## What worked well
- Every typed file matched the pack, the starters and solutions behave as stated, and the TS2322 text and position match exactly.
- "Common mistakes" for lesson 10 (TS2322) and lesson 08 (const) are real and exact; the warning "old output may remain, so never run after a failed build" is true and useful.
- The Windows file-extension step (View > Show > File name extensions) is correct and appears early.
- Icon provenance and CC0 license are handled correctly; alt text is taught (see 02-3 for its use).

## Top 5 fixes
1. **Tell learners where the packs are** (01-2, 02-1): add a download link or the SVG text for lesson 02, state the pack structure, remove the maintainer commands and `build_packs` mentions from learner text.
2. **Fix the viewport and device-mode gap in 05 to 07** (05-1, 06-1, 07-1): define viewport early, teach F12 and device mode (or describe "wide/medium/narrow" without pixel values).
3. **Make the Windows PowerShell and npx traps visible** (08-1, 10-4): put the real `npm.ps1 cannot be loaded` message and the `npm.cmd` fix beside the first npm command, and warn that `npx tsc` outside the project tries to install an unrelated `tsc` package.
4. **Re-time and slim lessons 08 to 12** (08-2, 09-2, 10-1, 10-6, 11-3, 12-1): honest times (90 min or split), move the tsconfig table and lockfile out of the lesson body, cut closure, hoisting and type-predicate talk from 12.
5. **Replace the copied Common-mistakes rows with tested ones** (04-1, 08-3, 09-1, 11-2, 12-2): real messages for wrong folder (`Cannot find module`), wrong id (`Cannot read properties of null`), missing `.js` (`ERR_MODULE_NOT_FOUND`), `TS18047` on the Clear all exercise.

## Verdict
**Request-changes.** The code, verification and exact error text are accurate and reproducible, and no lesson fails once Sam has the pack, but one Blocker (no way to get the pack or icon), the viewport and PowerShell gaps, and over-optimistic times in 08 to 12 will stall or discourage a real first-timer. Lessons 01 to 04 and 07 are close to Approve-with-nits after fixes 1, 2 and 5.
