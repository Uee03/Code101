# Rust 301: Phase 3 Production

**Written (not run).** The code, the configuration files and the expected output of these lessons were prepared by reading the code and the official documentation. Nothing has been compiled, scanned, built into an image or executed yet. If a result differs, trust your tool's real output and report it.

## Prerequisites and extraction
Finish phases 1 and 2 of this level. Use Rust/Cargo 1.100.0, edition 2024. Windows: right-click the ZIP, Extract All. macOS: double-click. Linux: use the file manager Extract action. Every lesson folder has `code`, `exercise/starter`, `exercise/solution` and `verify.json`; each package stands alone.

Downloading is optional: each lesson at `tutorials/rust/301-super-hero-to-legendary/phase-3-production/` shows every file in full, including `deny.toml`, the `Dockerfile`, `.dockerignore`, the two GitHub workflow files, the HTML page and the JavaScript. Read it in https://github.com/Uee03/Code101 (Code, Download ZIP, or git clone).

## Lessons and primary future commands
| Lesson | Working folder in this phase | Command | Needs |
|---|---|---|---|
| 08. Supply chain and security | `08-supply-chain-and-security/code` | `cargo generate-lockfile`, then `cargo run --quiet` | crate `subtle`; later `cargo-audit`, `cargo-deny` and Docker (temporary) |
| 09. WebAssembly, release engineering and the production review | `09-webassembly-and-release-engineering/code` | `cargo run --quiet --bin slug-cli` | crate `wasm-bindgen`; for the browser part `rustup target add wasm32-unknown-unknown`, `wasm-bindgen-cli` 0.2.130 and Python |

`cargo test` in the same folder runs the unit tests. **`Cargo.lock` is intentionally absent** because only Cargo can create it: run `cargo generate-lockfile` (or the first `cargo build`) and commit the file for an application. Lesson 08's `Dockerfile` copies `Cargo.lock` and builds with `--locked`, so it fails until you have created the lockfile.

## Exercise route
For each lesson, copy the `starter` folder from its `exercise` folder directly into `$HOME/code101/rust301` and rename the copy `tryNN` (the lesson's two-digit number). Do not create `tryNN` first and copy into it. Lesson 09's exercise is a **code review**: write your findings before you open the solution.

## Verification and limits
`verify.json` lists future deterministic runs of the native programs and the solutions only. It does not run `cargo audit`, `cargo deny`, Docker, the WebAssembly build or the CI workflows. The two workflow files have never been executed. Reproducibility of the image is something the lesson asks you to test, not something this pack claims.

## Stop and clean up
The Python web server in lesson 09 runs until you press Ctrl+C. Lesson 08 shows the exact commands that remove the containers, images and copied binaries it creates; it never uses a broad prune command. Delete the `lesson` and `try` folders and their `target` folders when you finish.

## Assets and generated files
No art is used (`assets: []`). The browser bundle (`web/pkg`) and the `pkg` folder are generated by `wasm-bindgen` and are listed in `.gitignore`. No lockfile, `.env` file, compiled binary or image is included.
