# csharp 101 walk-through by Sam (marketing, no coding)

Scope: `tutorials/csharp/101-zero-to-hero/` lessons 01 to 12, in order, Windows 11, Windows PowerShell 5.1, .NET SDK 11.0.100 (`dotnet --version` printed `11.0.100`, `dotnet --list-sdks` printed `11.0.100 [C:\Program Files\dotnet\sdk]`, both as in lesson 01).
Method: worked only in `%TEMP%\sam-csharp` (home folder redirected there, so `$HOME/code101/csharp/lessonNN` was typed literally). Unzipped `dist/packs/csharp-101-all.zip`; typed every Steps file by hand into new folders; ran with `dotnet run --project . --nologo`; piped keyboard input; started every exercise from its pack starter, solved it, then compared with the solution. Triggered every error in each Common mistakes table. Compared lesson code with `source/...`. Install text was judged against the official pages (fetched with curl). Nothing was installed or uninstalled. The temp folder was removed at the end.

Overall: **no lesson is blocked.** All 12 programs, 12 starters and 12 solutions run. Every code block is byte-identical to `source/.../code` and `exercise/solution`. Every Expected output is what really prints. The problems are in Common mistakes (rows that cannot happen or have the wrong cause), jargon order, load per lesson, repeated boilerplate and gaps in lesson 01.

Time (estimates for a first-timer; Sam's real typing and reading speed was not measured): 01 about 100 min (stated 60), 02 to 06 about 30 to 40 (stated 25), 07 about 45, 08 about 30, 09 about 35, 10 about 45, 11 about 45, 12 about 90 (stated 50).

## What worked (kept for the author)
- Every command names its folder; `Set-Location` recovery lines are present; no machine-specific paths; "dot on the tab = not saved" is present; new terminal after install is present; the files really are only the ones named.
- `dotnet new console ... --no-restore` created exactly `global.json`, `Lesson.csproj`, `Program.cs` and ran with the shown output.
- All 12 exercise starters give a visible TODO output; all 12 solutions produce the captured output.
- Source files have no BOM; pack has no `bin/`/`obj/`.

## Top 5 fixes
1. Rewrite the Common mistakes tables of 04, 06, 09, 12 (and add loop rows to 05, `$80`/`15%` to 03, and setup rows to 01): every row must be an error this lesson's code can show, with the real Cause (CS0219 in 04, CS8321 in 06, the lesson-03 copies in 09 and 12).
2. Cut the repeated boilerplate in 02 to 12 (zip, folder, global.json, csproj table, duplicated project files in each solution) and the 26-row file table plus the Step 8 rewrite in 01.
3. Re-scope the dense lessons (07, 10, 11, 12) and correct the times (01 about 100, 12 about 90); define terms before use (terminal/SDK/restore in 01, exception in 03, culture/interpolation in 02, static/object in 06, getter/public/private in 10).
4. Lesson 01 gaps: say where the pack comes from, paste the real first-run banner (telemetry and HTTPS certificate lines), and say plainly that C# Dev Kit sign-in is not needed.
5. Small text fixes: "01 through 01" in 02, the stray paragraph in 10 How it works, `lesson 01` self-link, `(09)` self-reference in 09, `Lesson.sourcelink.json` not generated, blank-line handling in 12.

## Notes from Sam's test run (not lesson findings)
- To see the first-run banner, Sam ran one `dotnet new` with a throw-away `DOTNET_CLI_HOME` inside the temp folder. That run printed "Installed an ASP.NET Core HTTPS development certificate", so Sam ran `dotnet dev-certs https --clean` afterwards (it reported three dev certificates and removed them). If that machine used those certificates for local web work, `dotnet dev-certs https` regenerates one.
- Ctrl+C on an infinite loop (lesson 05) cannot be typed through a pipe; not tested.
